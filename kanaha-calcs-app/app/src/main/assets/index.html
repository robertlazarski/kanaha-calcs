Kelly Fraction

#1 — Optimal bet sizing
You believe a stock has a 60% chance of going up 2x what it could lose. How much of your portfolio should you allocate? Try changing the win probability to 0.5 — the answer drops dramatically.
Learn More
f* = (b × p − q) / b
Kelly, J.L., Jr. (1956). “A New Interpretation of Information Rate.” Bell System Technical Journal, 35(4): 917–926.

The Kelly criterion determines the optimal fraction of capital to wager when the odds are in your favor. A result of 0.25 means bet 25% of your bankroll. Negative values mean the bet has negative expected value — don’t take it.

Kelly Odds (Payoff Ratio)

#2 — Reward-to-risk ratio
If your analyst says a stock could go to $150 (from $100) or drop to $80, that’s $50 reward vs $20 risk. This ratio is the “b” input for Kelly above.
Learn More
odds = |reward| / |risk|
Kelly, J.L., Jr. (1956). Section III. Bell System Technical Journal, 35(4): 917–926.

The payoff ratio is the “b” term in the Kelly formula. A ratio of 2.5:1 means you stand to gain 2.5x what you risk. This is one of the two inputs needed for Kelly sizing.

Sharpe Ratio

#3 — Risk-adjusted return
A fund returned 12% with 15% volatility while T-bills paid 4%. Is that good? Try raising volatility to 30% — the same return looks much worse per unit of risk.
Learn More
SR = (Rp − Rf) / σp
Sharpe, W.F. (1966). “Mutual Fund Performance.” The Journal of Business, 39(1): 119–138.

The Sharpe ratio measures excess return per unit of risk. SR > 1.0 is generally considered good; SR > 2.0 is excellent. A negative Sharpe means the portfolio underperforms the risk-free rate.

Normal Distribution Probability

#4 — Probability of a return
If a stock has 20% annual volatility, what’s the probability of losing 10% or more? Try changing to -30% — the probability drops to ~7%. These are the tails that VaR measures.
Learn More
Φ(z) where z = return / volatility
Abramowitz, M. & Stegun, I.A. (1964). Handbook of Mathematical Functions. NBS Applied Mathematics Series 55, §26.2.

Computes the probability that a normally distributed return falls below the given value. Uses the Abramowitz & Stegun rational approximation (formula 26.2.17) — no lookup table.

Covariance Matrix

#7 — Co-movement of returns (data-driven)
Learn More
cov(i,j) = Σ(ri − μi)(rj − μj) / (n−1) × 252
Pearson, K. (1896). “Mathematical Contributions to the Theory of Evolution. III.” Philosophical Transactions of the Royal Society A, 187: 253–318.

Log returns are computed from adjusted close prices, then annualized by multiplying by 252 (trading days per year). The correlation matrix is derived: ρ(i,j) = cov(i,j) / (σiσj).

Portfolio Variance

#16 — w'Σw matrix computation (Axis2/C)

σ²p = w' × Σ × w
Markowitz, H. (1952). “Portfolio Selection.” The Journal of Finance, 7(1): 77–91.

Portfolio variance is computed via matrix multiplication of the weight vector and the covariance matrix. Runs as native C code for performance — 500-asset matrices in ~150 μs.

Monte Carlo VaR

#17 — Value at Risk via simulation (Axis2/C)
Pick a stock, and the C engine simulates 10,000 possible futures for the next year using its historical return and volatility. The result tells you: “In 95% of simulated years, this stock did not lose more than $X.” That dollar amount is the Value at Risk. It runs as native C code on your phone — not JavaScript.
Learn More
S(t+dt) = S(t) × exp((μ − σ²/2)·dt + σ·√dt·Z)
Metropolis, N. & Ulam, S. (1949). “The Monte Carlo Method.” JASA, 44(247): 335–341.

How it works: The C engine takes today’s price and the stock’s historical return and volatility (computed from the loaded data). It generates 10,000 random price paths over 252 trading days using Geometric Brownian Motion — each path is one possible future year. Then it sorts all 10,000 final prices and reads off the worst outcomes:
  • 95% VaR = the price at the 5th percentile (only 5% of paths ended worse)
  • 99% VaR = the price at the 1st percentile (only 1% of paths ended worse)
  • Max Drawdown = the worst peak-to-trough drop across all paths
This is the same technique banks use for regulatory capital calculations, running on your phone in native C via Axis2/C.

Volatility source: When you select a different ticker as the volatility source, both its historical return and volatility are used for the simulation. This is regime analysis: “what would this asset do in a world that behaves like that market?” A natural extension would be to decouple return and volatility into independent inputs for pure stress testing (e.g., AAPL’s return with USDBRL’s vol).

Sampling precision: With 10,000 simulations, the 95th-percentile VaR has a standard error of roughly ±1–2% of the reported value. Running 100,000 sims would cut that by ~3×, but 10k is the standard tradeoff for speed on mobile ARM (<150ms in C).

Model assumptions: GBM assumes constant volatility and continuous price paths (no jumps). Real markets exhibit fat tails (leptokurtosis), volatility clustering, and discontinuous moves — so GBM systematically understates extreme tail risk. For better tail modeling, switch the Model dropdown to Merton jump-diffusion (Merton, 1976): GBM plus a compound Poisson jump process, drift-corrected so the expected terminal value is unchanged. GARCH-filtered simulations would be the next step. The native service architecture is pluggable: each model is one function in the C engine, added without changing the JS, Java bridge, or HTTP/2 transport.

See the math: The C source code (the simulation loop) implements the GBM formula step by step — you can follow the drift correction (μ−σ²/2), the random walk (σ√dt·Z), and the percentile sort that produces the VaR numbers. The code reads like the textbook equation even if you don’t know C syntax.
